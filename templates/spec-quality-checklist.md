# Чек-лист якості специфікації

Базова версія. На тижні 5 ти зробиш із неї власну.

## Повнота
- [ ] Мета пояснює проблему і як виміряти успіх
- [ ] Усі ролі перелічені, права вказані
- [ ] Кожна user story має acceptance criteria
- [ ] Кожна story має мінімум 2 негативні сценарії
- [ ] Edge cases розглянуті по всіх 5 категоріях
- [ ] Є out of scope

## Однозначність
- [ ] Кожен критерій перевіряється відповіддю «так/ні»
- [ ] Немає слів «швидко», «зручно», «інтуїтивно», «тощо», «і т.д.»
- [ ] Числа й ліміти вказані явно
- [ ] Терміни відповідають глосарію проєкту

## Чесність
- [ ] Невідоме позначене у «Відкритих питаннях», а не вигадане
- [ ] Спека не диктує технічну реалізацію (це зона інженера)

## Тест на агента
- [ ] Claude без контексту не знаходить критичних неоднозначностей
- [ ] Обсяг 1–3 сторінки
